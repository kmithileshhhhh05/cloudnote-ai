Abstract This study examines how a library of recorded lectures can be made to "remember itself": when one recording says "as we discussed earlier" or "in the next video", can a system find, or keep looking for, the recording that actually explains it? CloudNote AI is a web application that transcribes uploaded media with Amazon Transcribe, writes timestamped notes, answers questions only from those notes with numbered citations, detects backward references and forward follow-ups across videos, and re-checks unresolved references after every new upload. A separate, clearly labelled "Know more" function supplies general AI background when no video covers a topic. The system is deployed on a serverless AWS stack and was exercised against the live deployment. In a small live benchmark, transcript import to AI notes took a median of 4.6 s (n = 3) and an 11-s speech clip took a median of 17.3 s from upload to finished notes (n = 3). Ask-your-notes answered all five questions covered by the notes with citations and declined four of five off-topic questions; the fifth fell back to keyword search after a free-tier rate limit. Because the project's AWS account currently has a Bedrock quota of zero, the deployed language model is a third-party fallback (Groq), and semantic search is disabled. The demonstration library is illustrative, and the accuracy of reference recovery has not yet been measured on real lecture series. What follows is a report on a running system and the engineering choices behind it; learning gains were not measured.

Index Terms lecture video retrieval, speech recognition, note extraction, retrieval-augmented generation, citation grounding, serverless computing, cross-reference detection.

I. Introduction

Students increasingly learn from series of recorded lectures, tutorials and meetings. A single recording is rarely self-contained: speakers say "use the database settings from the earlier tutorial" or "we will cover indexes in the next video". When the viewer does not remember, or never watched, the earlier recording, the reference becomes a dead end. Search tools index each video separately and answer the question "where was this word said?", not "which recording explains what this one assumes?".

CloudNote AI addresses this gap with three ideas. First, every recording is converted into timestamped moments so that any note, answer or link can point to a playable position. Second, references between recordings are detected explicitly and treated as objects with a state: open, linked, or remembered for later checking. Third, AI-generated content is separated by provenance: answers grounded in the user's notes carry citations, and general explanations are labelled as background knowledge.

We contribute the following. (1) It describes an end-to-end serverless pipeline from upload to transcription, notes and retrieval. (2) It presents a cross-video reference engine with a "Remember the Missing Explanation" mechanism that re-checks unresolved references after each new upload; in the tools we reviewed we found none that does this, although we do not claim that none exists. (3) It describes grounded question answering with citation validation and abstention, plus a separate general-knowledge path. (4) It reports the first real deployment honestly, including provider quotas, fallbacks and measured behaviour.

II. Related Work

Extractive summarisation selects representative sentences rather than generating new text; graph-based centrality methods such as TextRank [1] remain a common unsupervised baseline. Term weighting with TF-IDF and cosine similarity [2] provides transparent lexical retrieval, while sentence embeddings such as Sentence-BERT [3] capture meaning beyond shared words. CloudNote AI uses lexical retrieval by default and supports 512-dimensional Amazon Titan embeddings when available.

Retrieval-augmented generation conditions a language model on retrieved passages to improve factual grounding [4]. Language models can still produce fluent but unsupported statements [5], which motivates requiring citations and checking them [6]. CloudNote AI follows this line: answers must cite numbered passages, and uncited answers are discarded rather than shown.

From a learning perspective, multimedia instruction research recommends reducing extraneous load, for example by signalling and by segmenting material [7]. Timestamped notes, a moments timeline and explicit links between recordings are intended as such signals; their educational effect has not been tested in this work.

III. System Design

A. Architecture

The system is fully serverless (Table I). A vanilla JavaScript single-page application is served from a private S3 bucket through CloudFront, which also forwards /api/* to an HTTP API. A Cognito JWT authoriser rejects unauthenticated requests before any function runs. All application state lives in one DynamoDB table keyed by user, so each user only ever reads their own library. Media is uploaded directly to a private S3 bucket using a presigned PUT and played back through short-lived signed URLs.

B. Processing Pipeline

After an upload, the API starts a Transcribe job named cn.<user>.<video>.<attempt>. An EventBridge rule matches completed or failed jobs with that prefix and invokes the worker, which parses the output into timestamped chunks. Users may instead import SRT, WebVTT, Transcribe JSON or plain text, which skips transcription. The worker then generates notes and updates the user's index and reference state.

C. Note Generation

For the model path, chunks are numbered and batched into prompts of at most about 5,500 words. The model returns a summary, key points, action items and decisions, each tied to a chunk number so that every item links to its moment. If no model answers, an extractive fallback ranks chunks by lexical centrality, keeps at most one key point per equal-length segment of the recording (up to eight), builds a three-sentence summary from the most central chunks, and finds action items and decisions with keyword patterns. The video header states which method produced the notes.

IV. Cross-Video Context Recovery

A. Detecting References

Six regular-expression patterns detect backward references (for example "as we discussed earlier", "from the previous tutorial") and seven detect forward follow-ups ("in the next video", "we will cover that later"). We preferred hand-written patterns to a trained classifier: every match can be explained by pointing at the rule that fired, and no training data is needed. How many real references the patterns miss in natural speech has not been measured.

B. Finding Candidate Sources

For each reference, a query is formed from the referring chunk and the following chunk, with words that describe the act of referring (such as "earlier", "tutorial", "video") removed so that the query describes the topic. Candidates come only from the user's other recordings; forward follow-ups consider only later recordings. In lexical mode a candidate must reach a TF-IDF cosine score of 0.30. In semantic mode the score combines embedding similarity with a 0.2 lexical weight and must reach 0.50. A score only nominates a candidate. A link is created solely by the user, who can accept a suggestion, choose a source by hand, or ask the system to keep watching.

C. Remembering Missing Explanations

A remembered reference becomes a pending record. After every new recording is indexed, pending references are re-scored against it, and a match produces a single notification, de-duplicated so that the same pair is never announced twice. Accepted links, open gaps and pending follow-ups feed a library map that draws dependencies between recordings, proposes a watch order (sources before the recordings that rely on them), and produces a copyable gaps report.

V. Grounded Answers and General Explanations

A. Ask Your Notes

Questions are answered from the user's notes, not from the open web. Keyword retrieval selects up to 25 passages, which are numbered in the prompt. The model is instructed to use only those passages, cite them as [n], stay under 90 words, and reply NOT_IN_NOTES when the passages do not contain the answer. The server normalises citation styles (comma-separated lists, numeric ranges, and full-width brackets with line markers, all observed from the deployed model) and discards any answer without a valid citation. The interface lists the cited sources with links to their moments.

B. Know More

When a reference has no candidate source, or a question finds nothing, the user can request a short general explanation. A separate endpoint asks the model for a topic name and at most 160 words of background, inferring the concept from the referring sentence when needed. The result is labelled "General AI explanation, not from your videos". Keeping this path separate preserves the guarantee that cited answers come only from the user's material.

VI. Deployment and Model Fallbacks

The intended language model is Amazon Nova Lite on Bedrock with Titan text embeddings. On first deployment the account's Bedrock quota was zero tokens per day for every model, a limit that is not adjustable through Service Quotas. The backend therefore tries providers in order: Bedrock, Groq (openai/gpt-oss-120b [8]) and Google Gemini, then the extractive fallback. Each provider has a time budget: 12 s per provider in the API, which must answer within API Gateway's 29-s limit, and 60 s or 240 s in the background worker. Bedrock resumes automatically once its quota is raised. Table II lists the faults found during the first deployment; each was fixed or worked around.

VII. Evaluation

A. Method

All measurements were taken on 29 October 2026 against the live deployment in AWS us-east-1, using one temporary account that was deleted afterwards. Requests were sent sequentially from a client machine in India, so the timings include intercontinental network latency. The library held the four illustrative sample recordings, three copies of a short imported transcript and three uploads of an 11-s speech clip produced with macOS text-to-speech. Notes and answers were produced by the Groq fallback. Semantic search was disabled, so search was lexical. With so few runs, these figures characterise one deployment on one day rather than general performance.

For the five covered questions, for example "Which port does the application use and why?", every answer cited at least one passage and agreed with the sample notes when we read it. Four of the five off-topic questions, such as "What is the capital of France?", were correctly declined. For the fifth, Groq returned HTTP 429 (free-tier rate limit) and Gemini timed out, so the system fell back to keyword search after 21.9 s and showed matching notes without an AI answer. The fallback behaved as designed, yet the episode shows that free-tier model access cannot be relied on when several requests arrive together.

VIII. Limitations, Privacy and Ethics

No labelled set of real lecture series exists yet for this task, so reference recovery has only been exercised, not scored. Because the sample recordings were authored to contain clear references, finding them there says little about messy, unscripted speech. The detection patterns are English-only although transcription supports Hindi, Telugu and other languages. Lexical search misses paraphrases until embeddings are enabled. The per-container in-memory index suits libraries of a few hundred recordings.

While a third-party provider is in use, transcript text leaves AWS for that provider, and users should not upload confidential recordings. The deployment allows open sign-up without email verification, and has no password reset; a production service needs restricted sign-up, verification, budget alarms and abuse controls. Generated notes and explanations can be wrong, which is why every grounded item links to its source moment and general explanations are labelled.

IX. Future Work

Planned work includes: a labelled dataset of references from several real lecture series to measure detection recall and candidate precision; enabling Bedrock and Titan embeddings and tuning the semantic thresholds (0.50 for references, 0.33 for questions) on that data; multilingual reference patterns; and a user study measuring whether linked recordings and remembered references reduce the time students need to recover missing context.

X. Conclusion

CloudNote AI shows that a serverless pipeline can turn recordings into timestamped notes, citation-checked answers and explicit links between videos, and can keep watching for explanations that do not exist yet. The live system works end to end, with interactive operations typically completing in a few seconds. What the project delivers is a deployed, open-source implementation of cross-video context recovery that others can run and audit. How accurately it links real lecture series, and whether it helps students learn, are the questions for the next stage.
